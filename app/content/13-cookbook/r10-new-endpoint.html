קבצים
  • server/app/services/cases_service.py — פונקציית service עם ה־SQL
  • server/app/api/cases.py — route (blueprint קיים; אין צורך לגעת ב־api/__init__.py)
  • client/src/api.ts — פונקציה (אם רוצים להשתמש בלקוח)
# services/cases_service.py
def status_counts(conn: Db | None = None) -> dict[str, int]:
    """How many publicly visible cases sit in each phase."""
    with owned(conn) as db:
        rows = db.query_all(
            f"SELECT c.status, COUNT(*) AS n FROM cases c "
            f"WHERE {PUBLIC_VISIBILITY} GROUP BY c.status"
        )
    return {row["status"]: int(row["n"]) for row in rows}

# api/cases.py
@bp.get("/cases/stats")
def case_stats():
    return jsonify({"counts": cases_service.status_counts()}), 200

// client/src/api.ts
export const fetchCaseStats = () =>
  request<{ counts: Partial<Record<CaseStatus, number>> }>("/cases/stats").then((r) => r.counts);

מה יכול להישבר / מה לומר
  • אין התנגשות עם /cases/<int:case_id> — ה־converter int לא יתאים ל־"stats" (כמו /cases/feed שכבר קיים).
  • שומרים על השכבות: SQL ב־service, ה־route רק קורא ומחזיר. אסור import flask ב־service (test_layering.py).
  • שימוש ב־PUBLIC_VISIBILITY — אחרת דולף מספר התיקים המוסתרים.
  • אם צריך auth: להוסיף @security.require_auth / @security.optional_auth מתחת ל־@bp.get.
  • מוסיפים import ב־api.ts של CaseStatus רק אם לא קיים — הוא כבר מיובא. import מיותר → npm run lint נכשל.
