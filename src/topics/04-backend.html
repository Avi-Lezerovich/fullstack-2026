4.1 נקודת כניסה ו־factory
  • server/run.py — מגדיר logging ברמת INFO ברמת המודול (כדי שיעבוד גם תחת gunicorn) ויוצר app = create_app(). הרצה ישירה (python run.py) מריצה את שרת הפיתוח של Flask עם threaded=True על settings.port (5002).
  • server/app/__init__.py:23 create_app() עושה 4 דברים: שומר Settings ב־app.config["SETTINGS"]; קובע MAX_CONTENT_LENGTH = upload_max_bytes + 8192 (413 לפני שה־view רץ); CORS על /api/* עם supports_credentials=True; register_blueprints(app).
  • server/app/api/__init__.py:44 — רושם 12 blueprints, כולם עם url_prefix="/api": health, auth, users, cases, social, trial, moderation, admin_ops, notifications, messages, assist, uploads.
  • בפרודקשן/דוקר: ה־CMD של server/Dockerfile מריץ gunicorn עם --worker-class gthread (ברירת מחדל 2 workers × 16 threads דרך GUNICORN_WORKERS/GUNICORN_THREADS).
4.2 שלוש השכבות ומחזור חיי בקשה
blueprint (api/*.py)   parse request → authorise (decorator) → call ONE service → map result code → status
services (services/)   all SQL + business rules. Never import Flask. Never raise for business outcomes.
db.py                  thin helper over PyMySQL: query_all / query_one / query_value / execute, owned(conn)
למה service מחזיר מחרוזת ולא זורק exception? כך כלל כמו "רק המחבר יכול למשוך תביעה" חי ב־service (cases_service.delete_case) ונבדק ב־unit test בלי request context — וה־worker (שאין לו Flask בכלל) יכול לקרוא לאותן פונקציות. טסט tests/unit/test_layering.py אוכף שה־services לא מייבאים Flask.

4.4 Auth — sessions, cookies, decorators
  • סיסמאות: bcrypt (BCRYPT_ROUNDS=12). security.password_problem() (security.py:59) — מינימום MIN_PASSWORD_LENGTH = 8 תווים ומקסימום 72 bytes (bcrypt 5 זורק במקום לקצץ).
  • Sessions: שורה בטבלת sessions לכל התחברות (הרבה לכל משתמש). auth_service.create_session() מייצר טוקן אקראי; העוגייה session_id נושאת את הטוקן הגולמי, וה־DB שומר רק token_hash = SHA-256.
  • Cookie flags (security.cookie_flags): תמיד httpOnly; SameSite=None; Secure כש־FLASK_SESSION_SECURE=1, אחרת Lax.
  • Decorators (security.py:137–182): @require_auth (401 לאנונימי; קובע g.user, g.user_id), @require_admin (401 / 403 בלי is_admin), @optional_auth (עובד גם אנונימי). _load_user מטמין את המשתמש ב־g כך שיש שאילתה אחת לבקשה.
  • Login (api/auth.py:51): אותה הודעה ל"אין משתמש" ו"סיסמה שגויה" — כדי שלא יהיה אפשר לגלות אילו אימיילים רשומים. משתמש banned → 403.
  • Password reset: טוקן חד־פעמי מוצפן ב־hash, תוקף RESET_TTL_MINUTES=30, cooldown RESET_COOLDOWN_SECONDS=60. ב־MAIL_BACKEND=console הקישור מודפס בלוג של השרת.
מלכודת כשה־decorator מחזיר 401 הוא גם מנקה את העוגייה (_unauthorised). login כושל מחזיר 401 רגיל ולא נוגע בעוגייה.
4.5 ולידציה (server/app/validation.py)

"קטן ומשעמם בכוונה": רק "האם השדה הוא מחרוזת סבירה בגודל הנכון". כללים עסקיים שייכים ל־service.

  • body_of(request) — get_json(silent=True); גוף שבור/חסר הופך ל־{} ואז 400 בעברית במקום 415 באנגלית.
  • clean(value, max_length) — ממיר למחרוזת, strip(), וחותך לאורך המקסימלי (לא דוחה!).
  • positive_int(value, default, maximum=) — לפרמטרי paging.
  • is_email, name_problem (NAME_MIN=2, NAME_MAX=80).

דוגמה — create_case ב־server/app/api/cases.py:65: כותרת < 3 תווים → 400 "כותרת התביעה קצרה מדי."; גוף < 10 → 400; תביעה נגד עצמך → 400; נתבע לא קיים/חסום → 400; אין נתבע בכלל → 400. מגבלות אורך: title 512, body 8000, comment 4000, message 2000.

4.7 טרנזקציות — owned(conn)
def some_service(..., conn: Db | None = None):
    with owned(conn) as db:      # server/app/db.py:195
        db.execute("UPDATE ... WHERE id = %s AND status = 'x'", (case_id,))
        db.commit_if_owned()       # commits only if WE opened the connection
  • אם הועבר conn — הקורא הוא הבעלים של הטרנזקציה (ה־service לא עושה commit/close). כך worker task מחבר כמה קריאות service לטרנזקציה אטומית אחת.
  • אם לא — ה־service פותח חיבור, עושה commit בהצלחה ותמיד סוגר.
  • autocommit כבוי. ExecResult.rowcount קריטי: כל מעבר מצב הוא UPDATE … WHERE status = 'expected', ו־rowcount 0 = worker אחר הקדים.
4.8 מודרציה, SSE והעלאות — בקיצור
  • 4 סטטוסים (cases + comments): published, flagged (עדיין ציבורי!), hidden, rejected. PUBLIC_VISIBILITY ב־cases_service.py:28. מודרציה לעולם לא מוחקת — רק מעבר סטטוס + שורה ב־moderation_actions.
  • Screen בזמן פרסום: moderation_service.screen() → sentiment.scan() באותה טרנזקציה של ה־INSERT. תוכן rejected עדיין נכתב (ראיה לתור האדמין) אבל ה־route מחזיר 422.
  • SSE (api/notifications.py:89): cursor מ־Last-Event-ID → ?since= → latest id; polling כל SSE_POLL_SECONDS=2; חיים מקסימליים SSE_MAX_SECONDS=300; מכסה SSE_MAX_STREAMS=50 לכל process (מעליה 503).
  • Uploads: שם הקובץ של הלקוח לא בשימוש (32 hex + סיומת שלנו), הפורמט לפי magic bytes, גודל נאכף 3 פעמים: nginx 6m, MAX_CONTENT_LENGTH, ובדיקה ב־view (UPLOAD_MAX_BYTES = 5 MiB).
