Tech stack — ולמה כל רכיב נבחר

רכיבבחירהלמה (כפי שמנומק בקוד/דוקים)
UIReact 18 + TypeScript + MUI 5קומפוננטות מוכנות עם תמיכה ב־RTL (direction: "rtl" ב־theme.ts) + stylis-plugin-rtl שהופך את ה־CSS הפיזי. TS תופס שגיאות בזמן build (tsc -b).
Build / devVitedev server מהיר על 5174 עם proxy ל־/api שמזרים SSE בלי buffering.
Routingreact-router-dom v6, BrowserRouterנתיבים נקיים; nginx עושה try_files … /index.html.
BackendFlask + blueprintsקטן ופשוט; blueprint לכל קבוצת משאבים.
DB accessPyMySQL גולמי, בלי ORMSQL פרמטרי מפורש; placeholders של MySQL (%s); הטסטים מריצים את אותו דיאלקט מול MySQL אמיתי.
WSGIgunicorn --worker-class gthreadstream של SSE מחזיק handler דקות; sync worker היה נחסם.
DBMySQL 8 InnoDB, utf8mb4עברית; FOR UPDATE SKIP LOCKED, GET_LOCK, UNIQUE keys שמחזיקים את ה־crash-safety.
Authbcrypt + session rows + httpOnly cookieJS לא יכול לקרוא את העוגייה; אפשר לבטל את כל ה־sessions של משתמש (ban / reset). רק SHA-256 של הטוקן נשמר.
Real-timeSSE (EventSource) + polling fallbackללא broker: cursor על notifications.id.
AIGemini (HTTP, urllib), Bedrock/Anthropic (SDK), gateway, + offlineהחבילות אופציונליות (import בתוך הפונקציה); offline דטרמיניסטי — האפליקציה רצה בלי שום key.
Moderationמילון משוקלל (sentiment.py) — לא LLMרץ באותה טרנזקציה כמו ה־INSERT: חייב להיות מהיר ודטרמיניסטי.
PackagingDocker multi-stage, nginx unprivilegedimage אחד לשרת (3 פקודות: api/worker/seed), image אחד ל־web. רץ כ־non-root.
Testspytest (+ real MySQL), vitest + Testing Libraryהאפליקציה נשענת על אילוצי DB — רק DB אמיתי בודק אותם.
