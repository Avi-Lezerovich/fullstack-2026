תקלות נפוצות בזמן המבחן — סימפטום, סיבה, פתרון

רוב הזמן שהולך לאיבוד במבחן הוא לא על השינוי עצמו, אלא על "למה אני לא רואה אותו". קודם מחפשים כאן את הסימפטום (או ב־Ctrl+K), ורק אחר כך מתחילים לנחש.

בדיקה ראשונה תמיד curl -s localhost:5002/api/health (או בדפדפן). מה רואים שם: האם ה־DB למעלה (database), מה ה־phase_minutes, ומתי ה־worker תיקתק לאחרונה (worker.seconds_since_tick). בדוקר אפשר גם דרך nginx: localhost:8080/api/health.

השינוי שלי לא מופיע

שיניתי קוד, ובדוקר כלום לא השתנה
הקוד אפוי בתוך ה־image. אין volume של קוד.
docker compose up --build -d server (שרת) / web (לקוח, nginx) / worker. שינוי ב־app/ שה־worker משתמש בו מחייב rebuild לשניהם.
שיניתי קוד שרת, ו־native כלום לא השתנה
python run.py לא נטען מחדש לבד.
Ctrl+C ומריצים שוב. גם ה־worker (python run_worker.py) צריך restart.
שיניתי UI והדפדפן מראה את הישן
מטמון, או שפתחת את 8080 (דוקר) במקום 5174 (vite).
רענון קשיח: Ctrl+Shift+R. ב־native עובדים על http://localhost:5174 (HMR מיידי).
שיניתי ערך ב־.env ובדוקר אין השפעה
compose מעביר לקונטיינר רק משתנים שמופיעים ב־environment. לא מועברים: UPLOAD_MAX_BYTES, SESSION_TTL_DAYS, RESET_TTL_MINUTES, SSE_*, BOT_COOLDOWN_MINUTES ועוד.
מוסיפים ל־environment: של השירות ב־docker-compose.yml, או משנים את ברירת המחדל ב־server/app/config.py. אחרי זה docker compose up -d server.
שיניתי ברירת מחדל ב־config.py ובדוקר אין השפעה
compose דורס אותה, למשל PHASE_MINUTES: ${PHASE_MINUTES:-1440}.
משנים את הערך ב־docker-compose.yml (בשני השירותים), או ב־.env. ראו מתכון 9.
שיניתי את init.sql ושום דבר לא קרה
MySQL מריץ את init.sql רק כשה־volume ריק.
מוחק נתונים: docker compose down -v ואז docker compose up --build. שומר נתונים: make db-shell ואז ALTER TABLE …

git: לחזור אחורה

git status                # מה שונה
git diff                  # השינוי עצמו, את זה מראים לבוחן
git checkout -- path/file # לבטל שינוי בקובץ אחד
git checkout .            # לבטל את כל השינויים בקבצים קיימים
git stash                 # להחביא שינויים (git stash pop מחזיר)

קבצים חדשים לא חוזרים עם git checkout .. מוחקים אותם ידנית, או עם git clean -fd, שמוחק לצמיתות כל קובץ שלא נמצא ב־git, אז קודם מסתכלים ב־git clean -n מה הוא היה מוחק.
