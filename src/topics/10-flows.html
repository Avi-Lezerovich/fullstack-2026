חמש הזרימות החשובות, עם הקבצים והפונקציות המדויקים בכל צעד. חיצים מקווקווים = תשובה. (התרשימים מצוירים כ־SVG ע"י סקריפט קטן בתוך הקובץ, מנתונים שכתובים ידנית.)

10.1 התחברות (Login)
  1. pages/Login.tsx → useAuth().signIn(email, password) (context/AuthContext.tsx).
  2. api.login() → POST /api/auth/login עם credentials: "include".
  3. api/auth.py:51 login(): clean(email).lower() → users_service.get_by_email → security.verify_password (bcrypt). נכשל → 401 "כתובת האימייל או הסיסמה שגויות." ; banned → 403.
  4. _authenticated_response → auth_service.create_session(user_id, ttl_days=SESSION_TTL_DAYS): INSERT INTO sessions (token_hash = sha256(raw)).
  5. security.set_session_cookie(response, raw_token) → 200 {"user": private_user(...)}.
  6. בבקשות הבאות: _load_user → auth_service.resolve_session(raw) לפי hash, תוקף, ו־status.
10.2 הגשת תביעה (File a case)
  1. pages/NewCase.tsx submit() → api.createCase({title, body, defendant_text, defendant_user_id, charges, image_url}).
  2. POST /api/cases → @security.require_auth → api/cases.py:65 create_case(): body_of, clean, בדיקות (כותרת ≥3, גוף ≥10, לא נגד עצמך, נתבע פעיל, יש נתבע).
  3. cases_service.create_case() (cases_service.py:246): moderation_service.screen(title+body) → sentiment.scan → status (published/flagged/rejected).
  4. INSERT INTO cases (… status='witness_phase', phase_deadline_at = now + witness_deadline_offset()), INSERT case_charges (clean_charges, עד 5), record_scan.
  5. אם לא rejected: case_activity_service.touch(case_id,"filed"), follows_service.follow(source="auto") למחבר ולנתבע הרשום. commit_if_owned().
  6. Route: "rejected" → 422; אחרת get_case → 201 {"case": …} → הלקוח navigate(/cases/<id>).
10.3 תגובה + התראה חיה (Comment → SSE)
  1. components/comments/CommentComposer.tsx → api.createComment(caseId, body, parentCommentId) → POST /api/cases/<id>/comments.
  2. api/social.py:98 create_comment(): גוף ריק → 400; תמיד role="user".
  3. comments_service.create_comment() (:79): screen → INSERT comments (depth עד MAX_DEPTH=3, root_comment_id) → _notify_participants → notifications_service.notify() למחבר התיק ולנתבע (לא לעצמך) → case_activity_service.touch → commit → 201.
  4. אצל המקבל: hooks/useNotificationStream.ts פתח new EventSource("/api/notifications/stream?since=…"); api/notifications.py:89 stream() סוקר כל SSE_POLL_SECONDS ושולח frame → NotificationContext מעדכן את הפעמון.
  5. אם SSE נכשל פעמיים תוך 30 שניות → polling ל־GET /api/notifications?since= כל 10 שניות.
10.4 מנוע המשפט (worker)
  1. יום 2: trial_tasks.advance_witness_phase → trial_service.advance_to_deliberation (:151): SELECT … FOR UPDATE, summons_service.mark_no_shows, jury_service.select_panel (pure, seeded ב־JURY_SEED_SALT, מוציא את הצדדים) → seat_panel (PK על case_id) → UPDATE cases SET status='jury_deliberation'.
  2. ימים 2–5: run_due_jurors → jury_service.due_jurors (speaks_at <= now AND spoke_at IS NULL) → trial_service.speak_as_juror (:210): _case_context → brain.deliberate() → {vote, line} → create_comment(role="jury_deliberation", dedupe_key="jury:<member_id>", screen=False) → jury_service.record_speech → memory_service.record_event(...,"vote") → commit.
  3. יום 6: advance_verdicts → trial_service.advance_to_verdict (:311): משלים מושבעים שותקים, count_votes → jury_service.tally(g, ng, judge_lean) → brain.generate(...,"verdict") (+ "sentence" אם אשם) → תגובה עם dedupe_key="verdict:<case_id>" → _notify_verdict.
  4. יום 7: close_cases → trial_service.close_case: UPDATE … status='closed' WHERE status='verdict_reached'.
