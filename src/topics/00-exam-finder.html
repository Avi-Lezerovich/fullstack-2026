מצב מבחן — ביקשו לשנות X, איפה זה?

הדף הזה הוא לשימוש בזמן המבחן. מוצאים את מה שביקשו לשנות ומקבלים את הקובץ והשורה, את המקומות שבהם אותו ערך משוכפל ("עדכן גם"), ואיך לוודא שזה עבד. כל נתיב עם ↗ נפתח בקוד עצמו בשורה הנכונה. Alt+לחיצה על נתיב פותחת אותו ישר ב־VS Code במחשב שלך, (ברירת המחדל היא C:SERSzRDOCUMENTSGITHUB ULLSTACK-2026, ואפשר לשנות אותה בכפתור למטה). בלי הגדרה, "העתק נתיב:שורה" נותן משהו שמדביקים ב־Ctrl+P ב־VS Code.

מתכוני שינוי (Cookbook)

לפני שמתחילים (5 דקות)

  • הפרויקט רץ: docker compose up --build → http://localhost:8080, או native (נושא 17).
  • התחברות: dana@lolsuit.local / demo1234. מנהל: admin@lolsuit.local.
  • git status נקי, כדי שבסוף git diff יראה רק את השינוי שלך.
  • הטסטים עוברים לפני שנוגעים (אחרת לא תדע מה שברת).
  • פתיחה ב־VS Code: לוחצים , מדביקים את נתיב תיקיית הפרויקט, ובודקים עם Alt+לחיצה על נתיב כלשהו.

כשמקבלים משימה: 5 צעדים

  1. שכבה: UI (client/src), route (api/), service (services/), סכמה (init.sql) או config?
  2. מצא כאן או ב־Ctrl+K. אחרי זה grep לערך עצמו, כי הרבה ערכים כתובים פעמיים (לקוח ושרת).
  3. שנה את המינימום שצריך. לא משנים שמות של ENUM או מפתחות API.
  4. הוכח: דפדפן, curl או DevTools → Network. בדוקר צריך rebuild לשירות ששונה.
  5. טסטים + git diff, ותסביר לבוחן מה עוד הושפע.

מה צריך כדי שהשינוי ייראה

  • client native (npm run dev, :5174): HMR, מיד.
  • server native (python run.py): Ctrl+C והרצה מחדש.
  • דוקר: docker compose up --build -d server (או web / worker). הקוד אפוי ב־image.
  • init.sql רץ רק על DB ריק: docker compose down -v או ALTER TABLE.
  • .env / compose: restart לשירות.
